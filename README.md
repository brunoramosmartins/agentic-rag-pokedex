# The Pokédex That Knows What It Hasn't Seen

> RAG agents answer with insufficient evidence instead of saying "I don't
> know". We build a world the model cannot remember, only read — and measure,
> step by step, whether it knows when it has not found the answer yet.

Pokémon is the tool, not the topic: the domain was chosen because it makes the
ground truth knowable **at every step** of a multi-step retrieval.

**Status:** Phase 0 — foundation, licensing and measurability gate. No results
yet; every hypothesis and decision rule is registered before the first number.

## The problem

In multi-step retrieval the bottleneck is not searching — it is deciding
whether the evidence gathered so far is enough. An agent whose sufficiency
detector is implicit (the model's own decision to stop or continue) tends to
stop early on plausible-but-insufficient evidence and to answer when the answer
does not exist in the corpus.

This project measures that decision with **exact, per-step labels**, no LLM
judge:

- **A controlled world.** PokéAPI data → a Neo4j graph → sectioned pages. For
  the primary population, every entity is renamed into a **counterfactual
  twin**, so parametric memory cannot stand in for evidence.
- **The graph as examiner.** Questions, gold answers, gold chains and the
  sufficiency label of every step are generated by construction. The graph is
  never a tool the agent can query.
- **Insufficiency by design.** Five strata: a sufficient control (S0), a
  missing hop (S1), the wrong game version (S2), a truncated set (S3), and no
  answer in the corpus (S4).
- **Arms.** Closed-book, single-shot, a fixed pipeline, an agent with an
  implicit detector, an agent with an explicit sufficiency judge, a depth
  placebo that searches just as much without knowing when to stop, and two
  oracles. Outcome: expected cost with a wrong answer costing more than an
  abstention.

It is the third project of a RAG trilogy: vector RAG that cites its source
(`rag-pix-regulation`), graph RAG for answers that are paths
(`graphrag-mtg-rules`), and now an agent that must know when it has not found
the answer.

## Project plan

Each phase is a GitHub milestone; issues are titled `[Phase N] ...`.

| Phase | Scope | Tag |
|---|---|---|
| 0 — Foundation | ADRs, licensing gate (G1), measurability gate, E-001 draft, scaffold | `v0.1-foundation` |
| 1 — World | PokéAPI → Neo4j → counterfactual twin → rendered pages → index | `v0.2-world` |
| 2 — Examiner | Question generator, gold chains, step labels, audit (G3) | `v0.3-examiner` (pre-release: benchmark) |
| 3 — Pilot gate | Typed-expansion experiment (E-002), pilot, preliminary G2 and G4 | `v0.4-pilot-gate` |
| 4 — Baselines | Closed-book, single-shot, fixed pipeline, 16× context, evidence oracle | `v0.5-baselines` |
| 5 — Agent | Agent loop, implicit and explicit detectors, depth placebo, stopping oracle | `v0.6-agent-detectors` |
| 6 — Layer 1 verdict | Dress rehearsal, single opening of eval-L1 | `v0.7-layer1-verdict` (pre-release) |
| 7 — Release | Demo and README | **`v1.0.0`** |
| 8–9 — Trained detector | Calibrated sufficiency classifier and its verdict | `v1.1.0` |
| 10 — External validity | MuSiQue, real world vs twin, second model | `v1.2.0` |

## Quickstart (development)

```bash
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env        # set NEO4J_PASSWORD
docker compose up -d        # Neo4j + Phoenix
pytest -m "not integration"
```
